# Phase 2 — Staff website

The Staff website is a static, responsive GitHub Pages application connected to
the Phase 1 Supabase project with the browser-safe publishable key. It does not
contain the Admin password, secret API key or service-role key.

## Staff flow

- `New Booking` validates every required field before calling `create_booking`.
- Each submission gets one browser-generated UUID that is reused if the network
  call is retried, matching the idempotency contract from Phase 1.
- Procedure selection is searchable and supports multiple values. Options use
  `procedure_catalog`, so historical popularity determines their order.
- Affected Region supports Ear, Nose, Neck and Throat. Patient Source keeps
  Clinic before Ward. Status and timestamps are generated by the database.
- On success, the form resets and the user moves to `Booking List`.

## Today's Booking List

- The public list contains only live records allowed by the database RLS policy,
  which means the current Malaysia day.
- Desktop uses a spreadsheet-style table; mobile uses readable cards.
- Staff can search and filter by All, Clinic or Ward, but cannot edit or delete.
- Supabase Realtime refreshes the list after a database event. Manual refresh,
  visibility refresh and a Malaysia-midnight refresh provide fallbacks.
- Clinic bed cases are orange. Ward cases are yellow, with an orange Procedure
  cell when the selected procedures require a bed.

Phase 2 is not the final production release. The Admin interface, statistics,
historical migration and staff short-link cutover remain in later phases.
